NEBULA -- confirmed Tauraro compiler/SDK/runtime defects
========================================================

The running log of Tauraro bugs hit while building Nebula, each reduced to a
minimal repro. Check here before spending time re-diagnosing a hang, a link
error naming a symbol you never wrote, or a value that is silently zero.

CLAUDE.md refers to a `tau_bugs.txt` from earlier sessions; that file is not
in the repo (it appears never to have been committed). This file replaces it.
Entries below numbered from 1; older entries referenced by number in CLAUDE.md
belong to the lost file and are NOT the same numbers.

Compiler: tauraroc, Windows SDK at %USERPROFILE%\.taupkg\bin\tauraroc-windows-x64
Recorded: 2026-09-06


--------------------------------------------------------------------------
#1  Module-level `mut` initializers DO NOT RUN on freestanding targets
--------------------------------------------------------------------------
SEVERITY  High -- silent wrong values, no crash, no diagnostic.
TARGETS   Any --freestanding build entered through `pub export def` rather
          than @entry/main. Confirmed on wasm32-freestanding; the same
          symptom was observed on x86_64-uefi.
STATUS    FIXED 2026-09-08 (tauraroc). Every `pub export def` now carries a
          shared, run-once guard: whichever exported function the host calls
          first runs the module's global initializers before its own body,
          so main()'s never-executed top-level-statement pass is no longer
          the only path that sets them. Existing workarounds (treating
          globals as zero and setting real defaults in a first-frame guard)
          remain harmless but are no longer required in new code.

REPRO
  mut plain_int: int   = 42
  mut computed:  int   = 6 * 7
  mut flag:      bool  = true
  mut small:     usize = 99 as usize

  pub export def get_plain_int() -> int:  return plain_int
  pub export def get_computed()  -> int:  return computed
  pub export def get_flag()      -> bool: return flag
  pub export def get_small()     -> usize: return small

  tauraroc probe.tr --target wasm --freestanding --emit c
  zig build-exe -target wasm32-freestanding -fno-entry -rdynamic \
      -O ReleaseSmall -femit-bin=probe.wasm -cflags -w -- build/main.c

  (needs @allocator/@free/@realloc/@calloc hooks present, or the C compile
  stops earlier with "TAURARO_KERNEL requires TAURARO_ALLOC/... defined")

OBSERVED
  get_plain_int() -> 0     (expected 42)
  get_computed()  -> 0     (expected 42)
  get_flag()      -> 0     (expected true)
  get_small()     -> 0     (expected 99)

CAUSE
  Global initialization is emitted into a module-init routine that only runs
  from main/_start. A freestanding entry point is called directly by its host
  (a zig UEFI stub, a JS host page), so that routine never runs and every
  global keeps its zeroed BSS value.

WHY IT IS NASTY
  Two distinct failure modes, and the second is much harder to spot:
    a) `mut x: SomeClass = SomeClass.init()` is permanently NULL. Fails later
       as "member access within null pointer of type 'UiParser'", far from
       the declaration.
    b) A SCALAR with a non-zero default is silently zero. Nothing crashes.
       A slider that declared `= 40` rendered at 0 across several verified
       screenshots before anyone noticed.

WORKAROUND
  Treat every freestanding global as zero-initialized regardless of its
  declaration. Assign non-zero defaults inside a function the host calls
  (a first-frame guard). See examples/web_demo/render_web.tr:reset_defaults.

#2  A >4KB stack frame fails to link on uefi-x64: undefined __chkstk
--------------------------------------------------------------------------
SEVERITY  Medium -- clear link error, but names a symbol absent from source
          and only on one target.
TARGETS   --target uefi-x64. Not hosted, not Cortex-M, not wasm.
STATUS    FIXED 2026-09-08 (tauraroc). The uefi-x64 turnkey build now passes
          -mno-stack-arg-probe to the C compiler, exactly the "real fix"
          named below -- no more split-per-family workaround needed for new
          code (existing splits are harmless to leave as-is).

REPRO
  One function with enough locals to cross a 4KB frame -- e.g. a long
  if/elif chain where each branch declares its own `mut`. Nebula's original
  toolkit/ui/style.tr:apply_utility had ~40 such branches.

OBSERVED
  lld-link: undefined symbol: __chkstk
    note: referenced by module_toolkit_ui_style.c  (apply_utility)

CAUSE
  __chkstk is the Microsoft x64 ABI's stack-probe helper, emitted for any
  frame larger than one 4KB page so the guard page is touched in order. UEFI
  shares that ABI (it is PE/COFF -- the same reason zig predefines _WIN32
  there) but is freestanding, so nothing supplies the helper.

WHY IT IS NASTY
  The trigger is TOTAL LOCALS IN ONE FUNCTION -- not recursion, not
  allocation -- so it accumulates silently as a function grows branches, and
  it is invisible on every other target.

WORKAROUND
  Split the function so no frame exceeds a page. Nebula split apply_utility
  into five per-family helpers. A real fix would be for the uefi-x64 target
  to provide __chkstk (~10 instructions) or compile with
  -mno-stack-arg-probe.

#3  Allocator hook names leak into tauraro_rt.h as macros and collide
--------------------------------------------------------------------------
SEVERITY  Medium -- confusing error naming a runtime type the user never
          referenced.
TARGETS   Any --freestanding build.
STATUS    FIXED 2026-09-08 (tauraroc). Each hook now routes through a
          uniquely-named static-inline wrapper (`_tr_hook_calloc` etc, guarded
          against the double-emission every hook already gets across
          tauraro_types.h + main.c) instead of substituting the user's chosen
          name straight into the macro body -- a hook can be named anything,
          including a single letter, with no collision risk.

REPRO
  @calloc
  def c(n: usize, sz: usize) -> Pointer[u8]:
      return some_alloc(n * sz)

OBSERVED
  build/tauraro_rt.h:1494:28: error: called object type '_TrChan *' is not a
  function or function pointer
      _TrChan* c = (_TrChan*)TAURARO_CALLOC(1, sizeof(_TrChan));
  note: expanded from macro 'TAURARO_CALLOC'
  #define TAURARO_CALLOC(n,sz) c(n,sz)

CAUSE
  Each hook becomes a bare textual macro (`#define TAURARO_CALLOC(n,sz)
  c(n,sz)`) that is then expanded INSIDE tauraro_rt.h, where the runtime has
  its own locals. A one-letter hook name shadows them.

WORKAROUND
  Give hooks distinctive names (`nebula_calloc`, `arena_calloc`). A real fix
  would emit the hook call through a uniquely-prefixed symbol rather than the
  user's chosen identifier.

#4  `--target wasm` alone cannot compile: tauraro_rt.h includes <stdio.h>
--------------------------------------------------------------------------
SEVERITY  Low -- clear error, but the fix is non-obvious from the message.
TARGETS   --target wasm without --freestanding.
STATUS    Open / arguably by design, but undocumented.

REPRO
  tauraroc probe.tr --target wasm -o probe

OBSERVED
  build/tauraro_rt.h:91:12: fatal error: 'stdio.h' file not found

CAUSE
  Bare wasm32-freestanding has no libc. tauraro_rt.h only skips the hosted
  headers when TAURARO_KERNEL is defined, and only --freestanding defines it.

WORKAROUND
  Always pair: `--target wasm --freestanding`. The cost is that the program
  must supply its own @allocator/@free/@realloc/@calloc.
  (`--target wasm-wasi` compiles as-is, because wasi-libc provides stdio --
  but it then imports wasi_snapshot_preview1, which a browser does not have.)

#5  `pub export def` is not exported from wasm without -rdynamic
--------------------------------------------------------------------------
SEVERITY  Medium -- no error at all; the symbol is simply absent at runtime.
TARGETS   wasm (both freestanding and wasi), when linking via zig build-exe.
STATUS    Open. Toolchain behavior; worth documenting because the failure is
          silent at build time.

REPRO
  pub export def add(a: int, b: int) -> int:
      return a + b

  ... link without -rdynamic ...

OBSERVED
  WebAssembly.Module.exports(mod) -> only [memory, _start]
  Calling instance.exports.add(...) -> TypeError: not a function

CAUSE
  wasm-ld drops unreferenced symbols. `pub export def` marks a symbol
  visible, but nothing references it inside the module, so it is stripped.

WORKAROUND
  Pass -rdynamic to zig build-exe (or an explicit --export=name per symbol).
  Nebula's scripts/build-web.ps1 and cli/ do this.


--------------------------------------------------------------------------
NOT BUGS -- language rules worth knowing (they cost time anyway)
--------------------------------------------------------------------------

* [L-1] Returning a module-level Pointer from a function is rejected: the
  compiler cannot prove the lifetime. Wrap in `unsafe:` or return the address
  as a `usize` instead. Nebula's nebula_init returns a byte offset for this
  reason (which JS wants anyway).

* WASM ABI: Tauraro `int` AND `usize` are both i64, so they arrive in JS as
  BigInt -- even on wasm32, where a pointer-sized type being 64-bit is
  surprising. Only `Pointer[T]` comes across as a plain i32 Number. Mixing
  them up gives "Cannot convert a BigInt value to a number", or worse,
  silently wrong offsets.

* Assigning a local into a field MOVES it ([M-1]); upcasting to an
  interface-typed variable also moves. Passing a concrete instance directly
  into a free function's interface parameter does not. This is why
  toolkit/ui/interp.tr has free-function wrappers (render_to,
  register_handler) rather than methods.

* `match` on an enum wants an explicit `case _:` even when every variant is
  listed, or the return-path checker ([F-3]) reports a missing return.

#6  `OS.args()` does not compile -- emits a call to a function that does
    not exist
--------------------------------------------------------------------------
SEVERITY  High -- the documented way to read argv is unusable, and it is the
          first thing any CLI reaches for.
TARGETS   All. Confirmed hosted (windows-x64).
STATUS    FIXED 2026-09-08 (tauraroc). `OS.args()` is now a real method
          (std/sys/os.tr) wrapping the same `_tr_get_argc`/`_tr_get_arg`
          primitives #6's workaround already used directly. The generated
          C `main()` also no longer names its own params `argc`/`argv` --
          renamed to `_tr_c_argc`/`_tr_c_argv` -- so a Tauraro local named
          either one inside `main()` no longer collides with them either.
          `_tr_get_arg` itself had a second, more serious bug found while
          fixing this one -- see the new #9 below; both are needed together
          for OS.args()/Env to be safe to use at all.

REPRO
  from sys.os import OS
  def main():
      mut a = OS.args()
      print("argc = " + len(a).to_str())

  tauraroc probe.tr --run

OBSERVED
  build/main.c:9:21: error: call to undeclared function 'OS_args'
  build/main.c:11:89: error: member referen ce type 'int' is not a pointer

CAUSE
  `OS.args()` lowers to a bare `OS_args()` call that nothing declares or
  defines -- the runtime has no such symbol. The follow-on error is the
  compiler then treating the implicit-int result as if it were a collection.

RELATED, AND WORSE
  Naming the receiving local `argv` inside `main()` adds a THIRD error:
      build/main.c:780:17: error: redefinition of 'argv'
  because the generated C main is `int main(int argc, char** argv)` and the
  user's local lands in the same scope. Any local named `argc`/`argv` in
  `main()` collides, regardless of OS.args().

WORKAROUND
  Declare the runtime primitives directly. These work correctly:

      extern "C":
          def _tr_get_argc() -> int
          def _tr_get_arg(n: int) -> str

  Verified: argc and every argv[i] come back correct, including argv[0] as
  the full exe path. This is what cli/nebula.tr uses.

#7  `Env.init()` crashes with heap corruption (0xC0000374)
--------------------------------------------------------------------------
SEVERITY  High -- the other documented argv path, and it takes the process
          down with no message.
TARGETS   Hosted windows-x64, compiled to .exe.
STATUS    FIXED 2026-09-08 (tauraroc). Root-caused: `_tr_get_arg` returned a
          BORROWED pointer straight into the process's real argv (owned by
          the CRT, never malloc'd), but codegen uniformly wraps every
          `-> str` extern result as OWNED and frees it later -- so the very
          first release corrupted the heap. Fixed at the runtime level
          (_tr_get_arg now returns a real owned copy via _tr_str_dup_owned,
          matching every other `-> str` helper's existing contract) plus a
          second, independent codegen bug found in the same investigation --
          see new #9 below. `Env.init()`/`all_args()`/`user_args()` all now
          work correctly; #6's raw-extern workaround is no longer necessary
          but remains harmless.

REPRO
  from sys.env import Env
  def main():
      print("A: before init")
      mut e = Env.init()
      print("B: count = " + e.get_arg_count().to_str())

  tauraroc probe.tr -o probe.exe   &&   .\probe.exe

OBSERVED
  No output at all (stdout is block-buffered and lost), process exits
  -1073740940 == 0xC0000374 == STATUS_HEAP_CORRUPTION.

NARROWED, BUT NOT SOLVED
  Ruled out, each verified working in isolation:
    * the four primitives Env.init() wraps -- _tr_get_argc, _tr_get_arg,
      _tr_exe_dir, _tr_cwd -- all return correct values;
    * `Vec[str].init(n)` plus `push()`/`get()`;
    * the use-after-move pattern in Env.init() (pushing a local `str` into a
      Vec and then concatenating with that same local afterwards) -- this
      does NOT corrupt anything on its own.
  So the fault is somewhere in the composition rather than any one part.
  Chasing it further needs a debug build or ASAN (`--debug`), which was not
  worth it once #6's workaround was confirmed.

WORKAROUND
  Do not construct Env. Use the raw externs from #6.

#8  `\` in a string literal produces NOTHING instead of a backslash
--------------------------------------------------------------------------
SEVERITY  High -- silently wrong strings, no diagnostic. Makes Windows paths
          impossible to write as literals.
TARGETS   All. Confirmed hosted (windows-x64), `--run` and compiled.
STATUS    FIXED 2026-09-08 (tauraroc). An unrecognized escape now keeps the
          backslash literally (`"C:\Users\Home"` round-trips correctly)
          instead of silently dropping it. Fixed in both `read_string` and
          `read_byte_string`. The forward-slash workaround is no longer
          necessary but remains harmless.

REPRO
  def main():
      print("1: [" + "a\b" + "]")
      print("2: [" + "C:\Users\Home" + "]")
      print("3: [" + "quote:\"q\"" + "]")
      print("4: [" + "tab:\there" + "]")
      print("5: len of a\b = " + "a\b".len().to_str())

OBSERVED                                 EXPECTED
  1: [ab]                                  1: [a\b]
  2: [C:UsersHome]                         2: [C:\Users\Home]
  3: [quote:"q"]            <- correct     3: [quote:"q"]
  4: [tab:<TAB>here]        <- correct     4: [tab:<TAB>here]
  5: len of ab = 2                         5: len of a\b = 3

CAUSE
  The literal scanner handles `\"` and `\t` but consumes `\` and emits no
  character at all -- not the backslash, not the two source characters. The
  length check rules out a display artifact: the backslash is genuinely
  absent from the string.

WHY IT IS NASTY
  Nothing warns. A path built this way is subtly wrong and only fails much
  later, wherever it is finally used. This showed up as

      'C:\Users\HomePC.taupkgbin' is not recognized as an internal or
      external command

  from a CLI whose source clearly read "\.taupkg\bin\\" -- the error names
  a path that appears nowhere in the source.

WORKAROUND
  Use forward slashes. Windows APIs, cmd.exe and PowerShell all accept them
  in paths. cli/nebula.tr builds every path this way for this reason.
  If a literal backslash is genuinely required, it cannot currently be
  written as a string literal at all.

#9  `List[str]`/`Vec[str]` .push()/.set()/.contains()/.index_of() silently
    double-wrap-and-release a fresh str argument -- use-after-free
--------------------------------------------------------------------------
SEVERITY  High -- no diagnostic, and the corruption is timing-dependent
          (garbage differs run to run, or doesn't reproduce at all depending
          on what happens to be sitting in the freed memory).
TARGETS   All. Found while fixing #6/#7; not something we'd hit a minimal
          repro for by hand, but real code hits it constantly -- ANY direct
          `.push(fresh_str_expr())` where the argument isn't first bound to
          a local (an extern call, a method call, a string concat, etc).
STATUS    FIXED 2026-09-08 (tauraroc). Root cause: the codegen for these four
          List[str]/Vec[str] methods called a str-argument helper
          (gen_args_strify) UNCONDITIONALLY, then overwrote its result with a
          second, independent call for the str-list case -- but the first,
          discarded call still had a side effect (it hoists a wrap/release
          temp into shared codegen state). The argument expression got
          evaluated and wrapped TWICE for one logical argument; both temps
          got released, double-freeing whatever the wrapped string
          ultimately pointed at. This is very likely the actual mechanism
          behind #7 above, which does exactly this shape internally
          (`result.push(_tr_get_arg(i))`).

REPRO
  extern "C":
      def _tr_get_arg(n: int) -> str
  def main():
      mut v: Vec[str] = Vec[str].init(0)
      v.push(_tr_get_arg(0))     # fresh extern-call result, not a local
      print(v.get(0))

OBSERVED
  Garbage/truncated string, or a hard crash (STATUS_HEAP_CORRUPTION on
  Windows) -- varies by run since it depends on what overwrites the freed
  block before it's read back.

WORKAROUND (no longer necessary, but harmless, and clarifies the shape)
  Bind the argument to a local first, then push the local:
      mut s = _tr_get_arg(0)
      v.push(s)
  This sidestepped the bug because a plain-local argument never went
  through the discarded-then-recomputed path that only fires for a FRESH
  (non-local) str expression.

#10  `from module import fn as alias` doesn't work for a free function
--------------------------------------------------------------------------
SEVERITY  Low -- clear compile error, easy one-line workaround, found in
          passing while wiring proposal v4 step B (Caps flags) and not
          chased further.
TARGETS   All. Confirmed hosted (windows-x64).
STATUS    FIXED 2026-09-08 (tauraroc). Root-caused and fixed in the compiler
          (src/parser.tr) -- see CAUSE/FIX below. The unqualified-import
          workaround still works and needs no reverting, but is no longer
          required for new code.

REPRO
  # toolkit/render/desktop/sdl_canvas.tr exports:
  #   pub def caps() -> Caps: ...
  from toolkit.render.desktop.sdl_canvas import caps as sdl_caps
  def main():
      print(sdl_caps().shadows)

OBSERVED
  build/main.c:1630:17: error: implicit declaration of function 'sdl_caps'
  build/main.c:1630:27: error: invalid type argument of '->' (have 'int')

CAUSE
  `ImportItem.alias` (src/ast.tr) was parsed correctly (`Name as Alias`) but
  was NEVER READ anywhere except src/fmt.tr's source formatter, which just
  echoes it back out. No resolver/sema/codegen pass ever bound the alias
  name to anything -- so `from module import x as y` silently behaved
  exactly like `from module import x`: only the ORIGINAL name `x` was ever
  callable, matching bindgen's docs being right for EXTERN-bound symbols
  (aliasing was never actually the mechanism there either -- likely a
  different, coincidental path) while a plain Tauraro-defined free function
  had no such luck.

FIX
  src/parser.tr: Parser gained an `import_aliases: Map[str, str]` field,
  populated in the `from module import ... as alias` parse path (records
  alias -> real name). Resolved at the CALL SITE, not via a broader
  identifier rewrite: `parse_postfix`'s `Token.LParen` case rewrites a bare
  `EIdent` callee to its real name immediately before building the `ECall`,
  if it matches a registered alias. Deliberately narrow -- only "a plain
  identifier immediately followed by `(`" is rewritten, so a local variable
  or parameter that happens to share a name with some OTHER file's alias is
  never touched (no scope/shadowing analysis needed). Works because
  Tauraro's unity build already makes every imported module's real names
  globally visible regardless of the import list (see the `from module
  import *` feature) -- the alias only ever needed to become a synonym for
  a name that was already reachable.

WORKAROUND (no longer required, kept for reference)
  Import the name unqualified and call it as-is:
      from toolkit.render.desktop.sdl_canvas import caps
      ...
      caps().shadows

#11  Reading a class's `str` field into a local does not retain it -- the
     local goes dangling once the owning object is replaced/freed
--------------------------------------------------------------------------
SEVERITY  High in principle (silent heap corruption, no crash, wrong data
          returned later) -- LOW blast radius found in nebula so far,
          because Interpreter.state's actual usage (proposal v4 step F)
          never needs a node_key to outlive the frame that produced it: a
          handler resolves and reads/writes state against the CURRENT
          Interpreter.root before the next render() call replaces it, not
          across renders. Found while writing step F's own regression test
          (verified-examples/node_identity.tr), which held a node_key
          across a render() specifically to prove structural stability --
          that test now avoids the pattern (see WORKAROUND) rather than
          exercising undefined behavior.
TARGETS   Default (C) backend. Not tested against --backend native/llvm.
STATUS    FIXED 2026-09-08 (tauraroc). Root-caused to the field-read
          boundary (see CAUSE) and fixed in src/codegen/c.tr -- see FIX
          below. Full gen1->gen2->gen3->gen4 self-host fixpoint verified
          (converged at gen3<->gen4, byte-identical --emit c output; one
          generation later than usual because the bug affected the OLD,
          unfixed compiler's own compilation of the compiler's source,
          which itself has this exact `mut x = obj.field` pattern
          throughout), full tests/lang + tests/regression suite (17 files)
          clean, all 37 examples/*.tr compile+run clean except two
          confirmed PRE-EXISTING failures unrelated to this fix
          (25_new_features.tr: unrelated Future-struct forward-declaration
          ordering bug; ffi_callbacks.tr: unrelated missing-link-symbol
          bug -- both reproduce identically on the pre-fix compiler).
          nebula's own workaround (never hold a node_key/str-field value
          across a render() boundary) remains correct and is NOT required
          to be reverted -- it was always the right design regardless of
          this fix (see verified-examples/node_identity.tr's own comment).

REPRO (minimal, outside nebula)
  pub class Node:
      pub key: str
  extend Node:
      pub def init(k: str) -> Node:
          mut n = Node()
          n.key = k
          return n
  pub class Holder:
      pub root: Node
  extend Holder:
      pub def init() -> Holder:
          mut h = Holder()
          h.root = Node.init("seed")
          return h
      pub def rebuild(self, base: str, idx: int) -> void:
          mut k = base + "." + idx.to_str()
          self.root = Node.init(k)
  def main():
      mut h = Holder.init()
      h.rebuild("0", 0)
      mut captured = h.root.key       # reads the str FIELD into a local
      print("immediately: " + captured)          # "0.0" -- correct
      mut junk: List[str] = []
      mut i = 0
      while i < 5000:                  # generate unrelated heap traffic
          junk.append("junkjunkjunkjunkjunk" + i.to_str())
          i = i + 1
      h.rebuild("0", 0)                 # frees the OLD Node, incl. its key
      print("after: " + captured)       # garbage ("captur" observed) --
                                         # `captured` was never retained, so
                                         # freeing the old Node's string and
                                         # later allocations reusing that
                                         # memory silently corrupt it.

CAUSE
  A companion repro proves the boundary precisely: keeping the WHOLE OLD
  OBJECT alive via a second local (`mut old = h.root`, a class-typed
  assignment) instead of just its field DOES protect `old.key` correctly
  across the same rebuild + allocation storm -- class-typed local
  assignment retains as expected. Only the narrower case -- a `str` FIELD
  read out of a class instance and bound to a `str`-typed local --  fails
  to retain. So the gap is specifically in str-field-read codegen, not
  class ARC in general and not string ARC in general (plain string locals
  and collection-stored strings are documented elsewhere as ARC-correct).

  Precisely: src/codegen/c.tr's `str_retain_wrap` (the function that
  decides whether a str-producing expression needs `_tr_str_retain()`
  before being bound) only retained an `EPropAccess` (field-read) source
  when `is_return` was true (a `-> str` return). The SLet/SAssign
  first-declaration codegen paths (a fresh `mut x = obj.field`) call it
  with `is_return=false`, so no retain ever happened there, AND the local
  was explicitly excluded from `str_local_names` tracking (the "this local
  owns a reference, release it at scope exit" bookkeeping) for exactly this
  source shape -- both halves of ownership were skipped, consistent with
  each other but wrong, since the field's owning object can be
  replaced/freed independently of this local's lifetime.

  The codebase had ALREADY found and fixed the identical gap once before,
  but only for REASSIGNMENT (`x = obj.field` where `x` already exists) and
  field-to-field STORES (`a.f = b.g`) -- b oth carry a comment tagged "#21"
  explaining precisely this same UAF and manually retaining around it. The
  fix was simply never extended to the first-declaration paths, which is
  exactly what nebula's repro hit (`mut captured = h.root.key`).

FIX
  Applied the SAME "#21-style" manual retain used at the already-fixed
  reassignment/field-store call sites to the two first-declaration paths
  that were missing it (src/codegen/c.tr, HirStmt.SLet and HirStmt.SAssign
  first-declare): when the RHS is an `EPropAccess`, wrap it in
  `_tr_str_retain(...)` and register the new local in `str_local_names` so
  it is released at scope exit like any other owned local (balancing the
  new retain). `str_retain_wrap` itself was left unchanged -- editing it to
  always retain would have double-retained at the already-patched
  reassignment/field-store sites, which apply their own manual retain on
  top of calling it.

WORKAROUND (no longer required now the compiler is fixed, kept for
context on why nebula's own code is still written this way)
  Never hold a class's str field in a local past a point where the owning
  object could be freed/replaced. Either:
    (a) keep the owning object itself alive in a local (`mut old = obj`)
        for as long as the field value is needed, since retain-on-class-
        assignment does work, or
    (b) re-read the field fresh from a still-live object instead of
        carrying an old copy forward.
  toolkit/ui/interp.tr's Interpreter.state (step F) never needs (a) or (b)
  for its real use: a click handler reads/writes state against
  Interpreter.root (still live) before the NEXT render() call ever runs,
  so no field value is ever held across the render() boundary that would
  free it. verified-examples/node_identity.tr's own structural-stability
  check now compares two independently-built, simultaneously-alive
  Interpreters instead of reusing one across two render() calls, and its
  state-persistence check uses pattern (a) explicitly -- left as-is since
  it was always the right design, not merely a bug workaround.


--------------------------------------------------------------------------
#12  `List[str]` index ASSIGNMENT does not compile -- generated C assigns
     `char *` to a `TrStr`
--------------------------------------------------------------------------
SEVERITY  Medium -- a hard compile error, so nothing silently breaks, but
          the error names generated C rather than the Tauraro line, and the
          same syntax on `List[int]` is documented as working (CLAUDE.md,
          "List[T] supports index assignment (px[i] = v) -- the framebuffer
          depends on this"), so it reads as a supported operation.
TARGETS   Default (C) backend, hosted. Not tested on other backends.
STATUS    Open. Worked around in cli/nebula.tr (see WORKAROUND).

REPRO
  def main():
      mut ints: List[int] = [1, 2, 3]
      ints[0] = 99                  # fine
      mut strs: List[str] = ["a", "b", "c"]
      mut tmp = strs[1]
      strs[0] = tmp                 # does not compile
      print(strs[0])

OBSERVED
  build/main.c:19:57: error: assigning to 'TrStr' from incompatible type
  'char *'
  1 error generated.

  Binding the right-hand side to a local first (as above) does NOT help --
  this is the ASSIGNMENT side, not the argument-wrapping path that #9 was.

CAUSE (inferred, not confirmed in the compiler source)
  The element-store path emits the raw `char *` payload where the list's
  slot type is the wrapped `TrStr`. `List[int]` is unaffected because its
  element type needs no wrapper.

WHY IT MATTERS
  It rules out in-place algorithms on string lists -- any sort, swap,
  reverse or rotate written the obvious way. Found writing an insertion
  sort over route names for folder-based routing; four assignments, four
  identical errors.

WORKAROUND
  Build a NEW list instead of mutating in place. A selection sort that
  appends the remaining minimum on each pass needs no element store (a
  parallel `List[bool]` tracks what has been taken -- bool elements assign
  fine, same as int). Slower on paper, irrelevant for the handful of items
  this shape usually involves.
